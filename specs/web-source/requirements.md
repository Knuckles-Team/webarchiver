# CONN-WEBARCHIVER-WEB-SOURCE — Requirements

Governing spec: [spec.md](spec.md).

Each row is one requirement. A child row `.n` is one five-minute unit of work. A row names the file it touches and the test that proves it. The generator sets each row's state in `status.json`.

| ID | Requirement | Acceptance |
|---|---|---|
| `CONN-WEBARCHIVER-WEB-SOURCE-R001` | **Pages answer through the web-source contract (rollup).** The webarchiver connector must implement the web-source contract of `SCION-SOURCE-INGEST-R005.40`. It serves the per-operation tools `web_fetch`, `web_extract`, `web_render` and `web_screenshot`. It is the primary backend of `research.web` (`ARBORA-OPS-R067.3`). Children `.1` to `.8` and `.10` deliver it. | See each child. |
| `CONN-WEBARCHIVER-WEB-SOURCE-R001.1` | **Model.** `web_fetch` and `web_extract` are the SDK web-source contract's tools (`SCION-SOURCE-INGEST-R005.40.1`). `register_web_source_tools` serves them over `WebarchiverSource` in `webarchiver/api/web_source.py`. They take a `WebFetchRequest` and return a `WebPageResult` or a `WebFetchRefusal`, with `backend=webarchiver`. `web_render`, `web_screenshot`, `web_links` and `web_crawl` are the connector's own per-operation tools. Proving test: `tests/test_conformance.py::test_webarchiver_conforms_to_the_web_source_contract`. | The served tool schemas equal the contract's, and an unknown argument is refused. |
| `CONN-WEBARCHIVER-WEB-SOURCE-R001.2` | **Behavior.** The connector must obey `robots.txt` for its user agent and cache each file for 3600 s. It must keep a per-domain rate limit of 1 request per second by default. It must stop reading at `max_bytes` and refuse an unlisted content type. `web_extract` must reduce the page to its main content as markdown. It must return the title, author, published date, canonical URL and outbound links. `content_digest` is the SHA-256 of the extracted text. Proving test: `tests/test_extract.py::test_main_content_and_metadata`. | Fixture pages yield the expected markdown and metadata, and a disallowed path is refused. |
| `CONN-WEBARCHIVER-WEB-SOURCE-R001.3` | **Wiring.** The browser capture in `Webarchiver.launch_browser` (`webarchiver/webarchiver.py:63`) serves `web_render` and `web_screenshot`. The server uses the SDK server factory and `register_tool_surface`. The production caller is `WebFetchSourceAdapter.extract` of `SCION-SOURCE-INGEST-R005.40.3`. Proving test: `tests/test_served.py::test_tools_call_reaches_extractor`. | A served `tools/call` reaches the extractor and the capture path. |
| `CONN-WEBARCHIVER-WEB-SOURCE-R001.4` | **Refusal.** Each refusal must use a closed reason of the contract: `robots_disallowed`, `rate_limited`, `size_exceeded`, `unsupported_type`, `egress_denied`, `policy_refused`, `extract_empty` or `upstream_failed`. A private address must refuse through the SDK egress policy. The connector must never return an empty page as a success. Proving test: `tests/test_extract.py::test_refusals`. | Each case returns its reason and no page body. |
| `CONN-WEBARCHIVER-WEB-SOURCE-R001.5` | **Evidence.** Each result must name `backend=webarchiver`, the final URL, the HTTP status, the byte count, the content digest, the retrieval time and the `robots.txt` decision. Proving test: `tests/test_extract.py::test_result_provenance`. | Each named field is present and matches the fixture response. |
| `CONN-WEBARCHIVER-WEB-SOURCE-R001.6` | **Hot-path proof.** The test serves the connector and runs the SDK conformance kit of `SCION-SOURCE-INGEST-R005.40.2` against it. It then runs `connector-sync --once` for one page into a running engine. Proving test: `tests/test_conformance_served.py::test_conformance_kit_and_sync`. | The kit reports no broken obligation, and the engine holds one Document with `backend=webarchiver`. |
| `CONN-WEBARCHIVER-WEB-SOURCE-R001.7` | **Bounded site crawl.** `web_crawl(seed_url, same_site, max_pages, max_depth, include, exclude)` in `webarchiver/api/crawl.py` must walk links breadth-first from one seed and return the page URLs it reached, in discovery order. It must fetch every page through the same policy as `web_fetch`: robots.txt, the per-domain rate limit, size and content-type caps and egress pinning. `same_site` defaults to true. `max_pages` ranges from 1 to 1000 and `max_depth` from 0 to 10. `include` and `exclude` are regular expressions. A robots-disallowed or failed page is reported as skipped with its closed reason. It returns URLs only; fetching content is the caller's next step. Proving test: `tests/test_crawl.py::test_bounded_crawl`. | A fixture site yields the expected URLs in order, the disallowed path is reported and never fetched, and out-of-range bounds refuse with `policy_refused`. |
| `CONN-WEBARCHIVER-WEB-SOURCE-R001.8` | **Ingest mappings.** `webarchiver/connector_manifest.yml` must declare `schema_mappings` for the `Document` and `Chunk` record types, mapped to the core `Document` and `Chunk` classes, so `SourceIngest` resolves `manifest:<connector>#schema_mappings/Document` and `.../Chunk` in the pack the fleet imports (`SCION-SOURCE-INGEST-R004.25`). Proving test: `tests/test_startup.py::test_manifest_maps_document_and_chunk_records`. | The served manifest maps both record types with their text, title, source and backend fields. |
| `CONN-WEBARCHIVER-WEB-SOURCE-R001.10` | **Conformance.** The connector passes the SDK conformance kit (`SCION-SOURCE-INGEST-R005.40.2`) against itself, served in process. The kit checks robots.txt, the per-domain rate limit, `max_bytes`, the content type, the digest and the tool schemas. The archivebox-api connector passes the same kit, so both produce the same tools and record shape (`CONN-ARCHIVEBOX-API-WEB-SOURCE-R001.8`). Proving test: `tests/test_conformance.py::test_webarchiver_conforms_to_the_web_source_contract`. | The kit reports no broken obligation. |
| `CONN-WEBARCHIVER-WEB-SOURCE-R001.11` | **Fleet name.** The connector files its content pack, manifest and ingest binding under its fleet name `webarchiver-mcp`, not the package name. `ConnectorContent.connector` in `webarchiver/mcp_server.py`, `connector` in `webarchiver/connector_manifest.yml` and the `IngestBinding` in `webarchiver/kg_ingest.py` all carry `webarchiver-mcp`, so the engine lists the connector's tools and ingest under the name the fleet and onboarding use. Proving test: `tests/test_startup.py::test_connector_name_is_the_fleet_name`. | The served content, the manifest and the ingest binding all name `webarchiver-mcp`. |
| `CONN-WEBARCHIVER-WEB-SOURCE-R002` | **Structured entity documents.** `web_fetch` must accept the media types `application/json` and `application/ld+json`. It returns the body unchanged, with its media type and `content_digest`. The digest is the SHA-256 of the body. It runs no markdown extraction on these types. The robots, rate-limit and `max_bytes` rules of R001.2 still apply. It serves `MEDULLA-DECISION-ENGINE-R099.2`. | Test: `tests/test_extract.py::test_json_entity_document_passes_through` fetches a fixture entity document and asserts the body, media type and digest. |
