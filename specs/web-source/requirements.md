Governing spec: [spec.md](spec.md).

| ID | Requirement | Acceptance |
|---|---|---|
| `CONN-WEBARCHIVER-WEB-SOURCE-R001` | **Pages answer through the web-source contract (rollup).** The webarchiver connector must implement the web-source contract of `SCION-SOURCE-INGEST-R005.40`. It serves the per-operation tools `web_fetch`, `web_extract`, `web_render` and `web_screenshot`. It is the primary backend of `research.web` (`ARBORA-OPS-R067.3`). Children `.1` to `.8` and `.10` deliver it. | See each child. |
| `CONN-WEBARCHIVER-WEB-SOURCE-R001.1` | **Model.** `web_fetch` and `web_extract` are the SDK web-source contract's tools (`SCION-SOURCE-INGEST-R005.40.1`). `register_web_source_tools` serves them over `WebarchiverSource` in `webarchiver/api/web_source.py`. They take a `WebFetchRequest` and return a `WebPageResult` or a `WebFetchRefusal`, with `backend=webarchiver`. `web_render`, `web_screenshot`, `web_links` and `web_crawl` are the connector's own per-operation tools. Caller chain: the `webarchiver-mcp` console script runs `webarchiver.mcp_server:mcp_server`, which calls `register_web_source_tools` (webarchiver/mcp_server.py:46) over `WebarchiverSource` (webarchiver/api/web_source.py:31). Shape: `WebarchiverSource` in `webarchiver/api/web_source.py` taking a `WebFetchRequest` and returning a `WebPage`; the SDK registers `web_fetch` and `web_extract`. Proving test: `tests/test_conformance.py::test_webarchiver_conforms_to_the_web_source_contract`. | The served tool schemas equal the contract's, and an unknown argument is refused. |
| `CONN-WEBARCHIVER-WEB-SOURCE-R001.2` | **Behavior.** The connector must obey `robots.txt` for its user agent and cache each file for 3600 s. It must keep a per-domain rate limit of 1 request per second by default. It must stop reading at `max_bytes` and refuse an unlisted content type. `web_extract` must reduce the page to its main content as markdown. It must return the title, author, published date, canonical URL and outbound links. `content_digest` is the SHA-256 of the extracted text. Caller chain: the `webarchiver-mcp` console script runs `webarchiver.mcp_server:mcp_server`, which calls `register_web_source_tools` (webarchiver/mcp_server.py:46) over `WebarchiverSource` (webarchiver/api/web_source.py:31); the fetcher in `webarchiver/api/fetcher.py` applies robots, rate and size policy of `webarchiver/api/policy.py`. Shape: `webarchiver/api/fetcher.py`, `webarchiver/api/policy.py` and `webarchiver/api/extraction.py`. Proving test: `tests/test_extract.py::test_fetch_follows_redirect_and_returns_html`. | Fixture pages yield the expected markdown and metadata, and a disallowed path is refused. |
| `CONN-WEBARCHIVER-WEB-SOURCE-R001.3` | **Wiring.** The browser capture in `Webarchiver.launch_browser` (`webarchiver/webarchiver.py:63`) serves `web_render` and `web_screenshot`. The server uses the SDK server factory and `register_tool_surface`. The production caller is `WebFetchSourceAdapter.extract` of `SCION-SOURCE-INGEST-R005.40.3`. Caller chain: an MCP client calls `web_render` or `web_screenshot`, registered by `register_tool_surface` in `webarchiver/mcp_server.py`, which reach `webarchiver/api/browser.py` through `Webarchiver.launch_browser`. Shape: `register_tool_surface` over `ApiClientSystem` in `webarchiver/mcp_server.py`; the browser capture in `webarchiver/api/browser.py`. Proving test: `tests/test_served.py::test_one_read_only_tool_per_operation`. | A served `tools/call` reaches the extractor and the capture path. |
| `CONN-WEBARCHIVER-WEB-SOURCE-R001.4` | **Refusal.** Each refusal must use a closed reason of the contract: `robots_disallowed`, `rate_limited`, `size_exceeded`, `unsupported_type`, `egress_denied`, `policy_refused`, `extract_empty` or `upstream_failed`. A private address must refuse through the SDK egress policy. The connector must never return an empty page as a success. Caller chain: the `webarchiver-mcp` console script runs `webarchiver.mcp_server:mcp_server`, which calls `register_web_source_tools` (webarchiver/mcp_server.py:46) over `WebarchiverSource` (webarchiver/api/web_source.py:31); refusals come from `webarchiver/api/policy.py` and `webarchiver/api/request_filter.py`. Shape: the closed refusal reasons of the SDK web-source contract raised by `webarchiver/api/policy.py`; private addresses refuse through the SDK egress check. Proving test: `tests/test_extract.py::test_refusals`. | Each case returns its reason and no page body. |
| `CONN-WEBARCHIVER-WEB-SOURCE-R001.5` | **Evidence.** Each result must name `backend=webarchiver`, the final URL, the HTTP status, the byte count, the content digest, the retrieval time and the `robots.txt` decision. Caller chain: the `webarchiver-mcp` console script runs `webarchiver.mcp_server:mcp_server`, which calls `register_web_source_tools` (webarchiver/mcp_server.py:46) over `WebarchiverSource` (webarchiver/api/web_source.py:31). Shape: result fields `backend`, final URL, status, byte count, content digest, retrieval time and robots decision set in `webarchiver/api/web_source.py`. Proving test: `tests/test_extract.py::test_result_provenance`. | Each named field is present and matches the fixture response. |

Shape: the served conformance run of `tests/test_conformance.py`; no code change. | `CONN-WEBARCHIVER-WEB-SOURCE-R001.7` | **Bounded site crawl.** `web_crawl(seed_url, same_site, max_pages, max_depth, include, exclude)` in `webarchiver/api/crawl.py` must walk links breadth-first from one seed and return the page URLs it reached, in discovery order. It must fetch every page through the same policy as `web_fetch`: robots.txt, the per-domain rate limit, size and content-type caps and egress pinning. `same_site` defaults to true. `max_pages` ranges from 1 to 1000 and `max_depth` from 0 to 10. `include` and `exclude` are regular expressions. A robots-disallowed or failed page is reported as skipped with its closed reason. It returns URLs only; fetching content is the caller's next step. Caller chain: an MCP client calls `web_crawl`, implemented in `webarchiver/api/crawl.py`, which fetches every page through the same fetcher. Shape: `web_crawl` in `webarchiver/api/crawl.py` walking links breadth-first with the bounds `max_pages` and `max_depth`. Proving test: `tests/test_crawl.py::test_bounded_crawl`. | A fixture site yields the expected URLs in order, the disallowed path is reported and never fetched, and out-of-range bounds refuse with `policy_refused`. |
| `CONN-WEBARCHIVER-WEB-SOURCE-R001.8` | **Ingest mappings.** `webarchiver/connector_manifest.yml` must declare `schema_mappings` for the `Document` and `Chunk` record types, mapped to the core `Document` and `Chunk` classes, so `SourceIngest` resolves `manifest:<connector>#schema_mappings/Document` and `../Chunk` in the pack the fleet imports (`SCION-SOURCE-INGEST-R004.25`). Caller chain: the ingest runner reads `webarchiver/connector_manifest.yml`, whose `schema_mappings` resolve `manifest:<connector>#schema_mappings/Document` and `Chunk`. Shape: `schema_mappings` for `Document` and `Chunk` in `webarchiver/connector_manifest.yml`. Proving test (planned): `tests/test_kg_ingest.py::test_manifest_maps_document_and_chunk`. | The served manifest maps both record types with their text, title, source and backend fields. |

Proving test: `tests/test_conformance.py::test_webarchiver_conforms_to_the_web_source_contract`. | The kit reports no broken obligation. |

| `CONN-WEBARCHIVER-WEB-SOURCE-R002` | **Structured entity documents.** `web_fetch` must accept the media types `application/json` and `application/ld+json`. The robots, rate-limit and `max_bytes` rules of R001.2 still apply. It serves `MEDULLA-DECISION-ENGINE-R099.2`. Caller chain: the `webarchiver-mcp` console script runs `webarchiver.mcp_server:mcp_server`, which calls `register_web_source_tools` (webarchiver/mcp_server.py:46) over `WebarchiverSource` (webarchiver/api/web_source.py:31). Shape: `WebarchiverSource` in `webarchiver/api/web_source.py` passes `application/json` and `application/ld+json` bodies through with a SHA-256 `content_digest` and no markdown extraction. | Test: `tests/test_extract.py::test_json_entity_document_passes_through` fetches a fixture entity document and asserts the body, media type and digest. |
